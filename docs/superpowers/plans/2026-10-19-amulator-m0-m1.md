# amulator M0~M1 구현 계획: 준비, bare-metal 미니 OS, AI 조작

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TypeScript로 짠 RV32 에뮬레이터를 만든다. 브라우저에서 bare-metal 그림판을 돌리고, 스냅샷으로 새로고침 뒤 이어서 실행하고, Claude Code가 MCP로 그림판에 그리고 화면을 캡처하게 한다.

**Architecture:** 세 패키지로 나눈다.

- `packages/core`: DOM·Node API 없이 CPU, 버스, 장치, 스냅샷, 제어 프로토콜을 담는다.
- `apps/web`: Vite 페이지다. Web Worker가 core를 구간 단위로 실행하고, OffscreenCanvas에 화면을 그리고, IndexedDB에 스냅샷을 둔다.
- `packages/mcp`: stdio MCP 서버다. 127.0.0.1의 빈 포트에 웹 페이지와 WebSocket 브리지를 띄우고, 도구 호출을 페이지로 넘긴다.

게스트는 clang으로 빌드한 bare-metal ELF다.

**Tech Stack:** pnpm 12.6 workspace, Node 22, TypeScript ~6.0.3, Vite ^8.3.4, Vitest ^5.0.5, @xterm/xterm ^6.0.0, zod ^4.6.7, @modelcontextprotocol/server ^2.3.1, @modelcontextprotocol/client ^2.3.1(테스트·스크립트), ws ^8.22.0, esbuild ^0.28.2, tsx ^4.23.15, LLVM clang + lld(riscv32), riscv-tests `d7e86f701b929b5d801f8cda1a4871ab05f452bb`. 버전은 2026-10-19 npm·GitHub 조회 값이다.

**Spec:** [docs/superpowers/specs/2026-10-19-amulator-design.md](../specs/2026-10-19-amulator-design.md). 이 계획은 설계의 M0과 M1만 다룬다. M2 이후는 M0에서 툴체인과 REA를 확인한 결과, 그리고 M2 관문 측정을 보고 따로 계획한다.

## Global Constraints

- TS·JS 코드를 쓰기 전에 conventions 스킬을 읽는다. 이 세션에서 스캐폴드하는 프로젝트다. 프리셋은 루트에 한 번 깔고, FSD 경계(boundaries) 블록과 react-hooks는 뺀다(사용자 결정).
- 코드 규칙: 화살표 함수, `type`, `as const` 객체(enum 금지), named export(설정 파일만 default), `any`·`as unknown as`·non-null `!` 금지를 지킨다. 외부 데이터(브리지 메시지, 스냅샷, ELF)는 경계에서 검증한다.
- `packages/core/src`는 DOM과 Node API를 쓰지 않는다. tsconfig `lib: ["ES2023"]`, `types: []`로 강제한다. 테스트 코드는 Node API를 써도 된다.
- 보조 스크립트는 node(`.mjs`)로 쓴다. `python`은 쓰지 않는다. 명령과 스크립트는 윈도우(Git Bash·PowerShell)와 맥에서 모두 돌아야 한다. 경로는 `node:path`로 만든다.
- SharedArrayBuffer와 COOP/COEP 헤더는 쓰지 않는다.
- 메모리 맵과 상수(`packages/core/src/memoryMap.ts`가 원본이고, `guest/baremetal/hw.h`가 같은 값을 갖는다):
  - RAM은 `0x8000_0000`부터 64 MiB(`0x400_0000`)다.
  - UART(16550)는 `0x1000_0000`, CLINT는 `0x1100_0000`이다. mini-rv32ima와 같은 주소다.
  - 프레임버퍼는 `0x1200_0000`이다. 320×480 크기, XRGB8888 리틀엔디언, stride 1280바이트다.
  - 터치는 `0x1300_0000`이고, timebase는 1 MHz(1틱 = 1µs)다.
- 문서와 커밋은 한국어 '-다'체로 쓴다. 커밋 제목은 `feat:` `fix:` `refactor:` `chore:` `docs:` `update:` 중 하나로 시작하고, 본문 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 단다. 플러그인 배포물(`plugin/skills/**`, 플러그인으로 묶이는 코드의 주석)은 영어로 쓴다.
- 커밋 직전에 브랜치와 `git status`를 다시 확인한다. 이 태스크가 만들지 않은 변경은 커밋에서 빼고 보고한다. 루트의 빈 `README.md`는 사용자 파일이므로 건드리지 않는다.
- `docs/learn/`은 사용자가 쓰는 학습 노트다. 에이전트는 이 폴더를 만들거나 고치지 않는다.
- 남의 에뮬레이터 코드를 복사하지 않는다. MIT 코드를 참고해 옮긴 부분이 있으면 그 파일 상단에 원 저작권 표시를 남긴다. LICENSE가 없는 r2의 코드는 참고하지 않는다.
- MCP 서버는 stdout에 로그를 쓰지 않는다. stdout은 MCP 전송로다. 로그는 stderr에만 쓴다.

## Review Focus

1. **탭 새로고침:** 페이지를 새로고침하면 브리지에 새 연결이 생긴다. 새 연결이 이기고, 이전 연결에 걸려 있던 요청은 끊김 오류로 끝나야 하며, 다음 도구 호출은 새 탭으로 간다. → Task 13 테스트
2. **IndexedDB를 못 쓰는 환경:** 시크릿 창이나 저장소 차단 상태에서도 페이지는 새로 부팅해야 한다. 저장 실패는 화면에 오류로 보이되 실행은 멈추지 않는다. → Task 11 테스트
3. **좌표 경계:** canvas 밖에서 손을 떼거나 CSS로 늘어난 canvas를 눌러도 좌표는 0..319, 0..479 안으로 잘린다. 브리지에서 들어온 범위 밖 좌표는 거부한다. → Task 9·11·12 테스트
4. **응답 없는 탭:** 페이지가 응답하지 않으면 도구 호출이 무한정 기다리지 않는다. 10초 뒤 오류 결과로 끝난다. → Task 13 테스트
5. **세션 여러 개:** 같은 폴더에서 Claude Code 세션 둘이 MCP 서버를 동시에 띄워도 포트가 겹치지 않고, 각자 자기 페이지를 서빙한다. → Task 13 테스트

### Task 4: 버스와 ELF 로더

**Files:**
- Create: `packages/core/src/bus.ts`, `packages/core/src/elf.ts`
- Test: `packages/core/test/bus.test.ts`, `packages/core/test/elf.test.ts`

**Interfaces:**
- Consumes: `memoryMap.ts`의 `RAM_BASE`, `RAM_SIZE`
- Produces:
  ```ts
  // bus.ts
  export type AccessWidth = 1 | 2 | 4;
  export type Device = {
    readonly base: number;
    readonly size: number;
    read: (offset: number, width: AccessWidth) => number;
    write: (offset: number, width: AccessWidth, value: number) => void;
  };
  export class BusFault extends Error { constructor(readonly address: number, readonly access: 'read' | 'write' | 'fetch') }
  export type Bus = {
    readonly ram: Uint8Array;
    read: (address: number, width: AccessWidth) => number; // 부호 없는 값(>>> 0)
    write: (address: number, width: AccessWidth, value: number) => void;
    fetch: (address: number) => number;
  };
  export const createBus: (ram: Uint8Array, devices: readonly Device[]) => Bus;
  // elf.ts
  export type ElfSegment = { paddr: number; data: Uint8Array; memsz: number };
  export type ElfImage = { entry: number; segments: ElfSegment[]; symbols: ReadonlyMap<string, number> };
  export class ElfError extends Error {}
  export const parseElf32: (bytes: Uint8Array) => ElfImage;
  export const loadElfIntoRam: (ram: Uint8Array, image: ElfImage) => void;
  ```

- [ ] **Step 1: 실패하는 테스트를 쓴다.**
  - `bus.test.ts`:
    - (a) `write(RAM_BASE, 4, 0x11223344)` 뒤 `read(RAM_BASE, 1) === 0x44`, `read(RAM_BASE, 4) === 0x11223344`. 리틀엔디언 확인이다.
    - (b) `read(RAM_BASE + 1, 4)`처럼 RAM 안에서 정렬되지 않은 접근도 바이트 순서대로 읽힌다.
    - (c) base `0x1000_0000`, size `0x100`인 가짜 장치에 `write(0x1000_0004, 1, 7)`을 하면 장치가 `offset 4`, `value 7`을 받는다.
