# amulator M0~M1 후속 작업 목록

- 작성일: 2026-10-20
- 출처: M0~M1 계획 실행 중 태스크 리뷰와 최종 전체 리뷰(Opus)가 남긴 지적 가운데 고치지 않고 미룬 것. 분류는 최종 리뷰의 판정을 따른다.
- 계획: [2026-10-19-amulator-m0-m1.md](../plans/2026-10-19-amulator-m0-m1.md)

## M5 공개 전에 처리할 것

- 브리지 오류 문구가 한국어라 플러그인 도구 결과에 그대로 섞인다(`apps/web/src/worker/emulatorWorker.ts`, `packages/core/src/control/protocol.ts`, httpSnapshotStore). 브리지로 나가는 문구만 영어로 바꾼다.
- `packages/mcp/src/openBrowser.ts`가 `cmd`를 찾을 때 libuv가 현재 폴더를 PATH보다 먼저 본다. `ComSpec`을 쓴다. 이때 eslint의 env 규칙(FSD 잔재, `src/shared/config`만 허용)이 막으므로 같이 정리한다.
- 플러그인 배포물에 `plugin/server`와 `plugin/web`이 없다(gitignore). 릴리스 단계나 CI에서 빌드 결과를 포함해야 마켓플레이스 설치가 동작한다.
- docs에 로컬 사용자 경로(`C:\Users\...`)가 남아 있다.
- 루트 `package.json`에 `engines`(Node ≥ 22)와 `packageManager`가 없다.

## 학습 노트 전에 고칠 것 (2026-10-19 처리)

가이드·REA 문서 지적 네 건(MPIE 읽을거리, displayId + 1, `settleIdle` 경로, REA 시작 제한 값과 프로세스 검색 기준)은 고쳤다. 남은 것: 상류 QEMU가 2020년에 "xRET 뒤 xPIE를 1로" 고쳤다는 패치는 미러에서만 봤다(미확인). 가이드에는 넣지 않았다.

## 나중에 처리해도 되는 것

### 테스트 보강

- riscv-tests 하네스가 ELF 개수(66)를 단언하지 않는다. skip한 테스트가 여전히 실패하는지 확인하지 않는다.
- bus: 가짜 장치 read의 offset·width 미검증. elf: ELFCLASS64, 빅엔디언, filesz > memsz, strtab 링크 방어 분기 테스트 없음.
- cpu: jalr 홀수 rs1 + imm 0, addi 0x400 패턴, lw/lui/auipc의 x0 목적지 테스트 없음. csrrs rs1=x2 케이스가 값 1이라 "번호 기준 쓰기"를 고정하지 못한다.
- machine: CLINT 쓰기 훅과 256명령 sync를 직접 겨냥한 테스트 없음.
- paint: 붓 3×3 크기, 선 연속성(한 점만 확인), 빈 큐 POP 단언 없음. `FB_STRIDE === FB_WIDTH * 4` 불변식 테스트 없음.
- snapshot: 입력 크기 경계(4바이트 미만, 4~11바이트, 큰 offset), RAM 크기가 4의 배수가 아닌 경우, 큐가 찬 채 저장한 뒤 실행을 이어 가는 경로.
- web: worker 대기자·타임아웃·취소 로직은 Node 테스트가 없고 브라우저 확인에만 기댄다. dragEvents `steps=1` 테스트 없음.
- mcp: 교체 시 failPending·Content-Length 사전검사를 지워도 테스트가 통과한다(변이 생존). tools 테스트의 x:400 케이스가 스키마 거부를 구분하지 못한다. stdio 테스트 블록이 순서에 의존한다. stdin 'close'만 오는 경로의 단독 회귀 테스트가 없다.
- e2e: 스냅샷 파일명·크기를 응답과 대조하지 않는다.

### 동작·견고성

- `snapshot.ts`의 정규식에 보이지 않는 U+FFFF 리터럴 문자가 있다. `\uffff`로 바꾼다.
- 스냅샷 `createdAt`이 `new Date()`라 직렬화 결과가 비결정적이다. UART rx 스키마에 길이 상한이 없다.
- `Machine.loadElf`가 CSR·CLINT·UART·래치를 리셋하지 않는다(지금은 세션이 항상 새 머신을 만든다).
- web: pause 중 Reset·snapshot.load 때 사람에게 보이는 캔버스가 낡는다. snapshot.load 실패 사유가 구분되지 않는다. pendingTouch에 상한이 없다. 부팅 전 tap/drag는 -32000이다(스킬이 screenshot 먼저를 안내한다). `?token=` 빈 문자열을 MCP 모드로 본다. IndexedDB onerror에서 request.error를 잃는다. pointerdown이 오른쪽 버튼을 거르지 않는다. createSession이 머신을 두 번 만든다.
- mcp: 한도를 넘는 큰 업로드에 413 대신 ECONNRESET이 간다. 윈도우에서 같은 key를 GET하는 중에 PUT하면 rename이 EPERM으로 500이 된다. 연결 전에 emulator_open을 두 번 부르면 탭이 둘 열린다. `Already connected`의 URL이 연결된 탭의 프로그램과 다를 수 있다.
- 툴체인 스크립트: checkToolchain의 CLI 가드가 심볼릭 링크와 argv[1] 없음에서 어긋난다. `--llvm-bin` 잘못된 경로를 조용히 무시한다. 전처리 실패 때 spawn error와 maxBuffer가 드러나지 않는다. `-Qunused-arguments`가 모든 미사용 인자 경고를 가린다.

### 정리

- eslint `**/*.config.ts` override가 `.mts`/`.cts`를 못 잡는다.
- `@types/node` ^26과 런타임 Node 22의 메이저가 다르다.
- `.gitattributes`에 `*.elf binary`가 없다(지금은 NUL 바이트로 binary 판정됨). `hw.h`의 `FB_STRIDE`가 리터럴이다. CLINT 오프셋이 hw.h·clint.ts·테스트 세 곳에 있다.
- `csr.ts`의 Counter export, pmpcfg1~2·pmpaddr1~14 이름 상수, `cpu.ts` 437줄(mulhu·mulDiv 분리 후보).
- `encode.ts`가 범위 밖 즉시값을 조용히 자른다.
- e2e `timed`의 value 미사용, 재시도 상한이 시도 사이만 검사.
- conventions 스킬 프리셋의 `eslint.config.mjs`가 prettier를 통과하지 못한다(레포 밖, 스킬 쪽 수정 거리).
